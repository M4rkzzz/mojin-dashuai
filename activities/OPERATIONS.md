# 四服活动 · 1.0.4

> 2026-09-07 已发布统一端 1.0.4，更新序号 23。API 1.2.3、热配置 revision 3 和一／二／三服观察器已部署。四服有玩家在线，观察器等待无人后升级；原日常和投递可继续，新增核心持有资格要等这次升级后才能自动记录。

统一端新增活动入口。游戏端只观察正常任务、制作、冶炼、战斗和四服 GT6 实际机器产出，不改配方、原任务奖励、世界或角色进度。

## 已落地规则

- 北京时间每日一次签到，同一个入服身份在四服中选择一服领奖。以前已完成未领取的日期保留。
- 每服三个日常选项，完成一项即可；周活动三步或三天日常。签到 1 券、1 章及小份补给；周活动 2 券、3 章。
- 普通／精选／稀有基础概率为 80%／18%／2%；49 次未出稀有，下次必得。券、纪念章、保底永久保留。
- 稀有结构奖按原任务、实际模组结构清单给完整一套，包含控制器与全部结构件；每个结构目标最多一套。原任务须已开放或完成，各结构件须有本人生产记录。魔法金属仪式核心等自定义机器产物通过服务端核实本人背包中已持有该核心，不能领取自己的第一份核心；这种持有证明仅解锁奖励，不算制作或签到。暂无合格奖励时保留中奖资格。
- 结构整套不再受旧版单次约 15%／累计 30% 材料上限约束；旧版部分材料奖励停止进入新奖池，既有投递、物品数量和历史记录保持原样。旧部分补给不抵扣新的一套资格。
- 8／20／40 章兑换主题称号、头像框和展示背景，不增加游戏属性。玩家分享需人工审核。
- 新奖池共 114 种抽奖奖励，另有 16 份签到补给配置，使用 111 份对应各服版本的真实游戏道具贴图。37 份旧配置标为 retired，只供历史与已有投递使用。catalog.json 是执行配置，reward-audit.json 是原任务用量依据，texture-sources.json 记录实际 JAR 贴图来源。
- 箱子插画仅作为抽奖装饰；火把、材料等道具均使用游戏内原贴图。界面包含切换、领取及开奖动画，并支持减少动态效果。

## 四服通用活动接口与热发布

四服统一使用 `/internal/v1/activities/{instance}/definition`、`events`、`deliveries` 和 `ack`，实例 ID 为 `m3e`、`dc2`、`mb`、`vw`。接口仍限制内网来源与各服独立凭据。任务系统差异留在观察器适配层，日常目标、章节前置、制作物品、击杀目标和奖励清单全部从配置读取。

运行中的 API 每 5 秒读取持久配置 `/data/activities-live/catalog.json` 的变更，验证成功后一次性切换；非法配置保留旧规则。游戏端最多 60 秒刷新，统一端活动页每 15 秒刷新。配置路径映射到 NAS `/vol1/mc-client-hub/api/activities-live/`，后续 API 升级会保留它及历史版本。

配置发布不重启 API 或游戏服务器：

```sh
# 查看当前配置版本，以及导出任意一服配置。
docker exec mc-client-hub-hub-api-1 dotnet Hub.Api.dll admin activities-config show
docker exec mc-client-hub-hub-api-1 dotnet Hub.Api.dll admin activities-config show m3e > /tmp/m3e.json
# 修改并审核 JSON 后放入容器；3 必须替换为 show 返回的当前版本。
docker cp /tmp/m3e.json mc-client-hub-hub-api-1:/tmp/m3e.json
docker exec mc-client-hub-hub-api-1 dotnet Hub.Api.dll admin activities-config validate m3e /tmp/m3e.json 3
docker exec mc-client-hub-hub-api-1 dotnet Hub.Api.dll admin activities-config apply m3e /tmp/m3e.json 3
```

`all` 可代替服 ID 一次提交四服 catalog。每次发布自动增加版本，旧版本并发发布会拒绝，历史配置保存到 `history/`。回退也以新版本提交历史 JSON，不手动降低版本号。

奖励数量、物品或前置改变时使用新奖励 ID；从新清单移除的旧奖品自动保留为 retired，不再抽出，但历史数量和已领取记录不变。已登记的任务、物品与击杀事实保留，避免离线事件丢失。已参与玩家的本周目标锁定到周末，新周期采用新目标，未领取的旧日常仍按原条件领取。奖池与新参与玩家目标在线生效。新增不受现有观察器支持的游戏事件、任务系统或模组适配属于代码升级，仍需无人时重启。

未人工核定的弹药、食品、下一阶段机器和关键解锁道具不进入首版奖池。后续扩池仍须核对原物品、NBT、数量、用途、前置与排除条件，不用通用电压等级代替 GT6 章节。

## 部署与回退

NAS 运行 `python3 /tmp/mojin-activities-deploy.py status` 查看各服状态。
`activate m3e|dc2|mb|vw` 会检查在线人数，保存后再检查一次；仅 0 人时正常 stop。等待退出后修改启动参数、启动并验证 RCON 与实际 JVM。人数不明或有人直接延期，不强杀游戏。

暂存及备份：`/var/apps/mc-client-hub/staging/activities-1.0.3`。各服私有配置、事件队列位于实例 `.activities`；不公开 secret 或环境文件。

本次观察器升级：`upgrade <服> --agent /tmp/mojin-activities-1.0.4.jar --version 1.0.4`。仅无人时正常重启，已有新版本会跳过。各服旧 JAR 和升级记录保存在 `staging/activities-1.0.4/<服>/`；`.activities/spool/status.json` 记录实际运行版本、规则刷新时间与追踪项数量。

关闭活动：先将 API 私有环境 `Activities__Enabled=false` 并仅重建 hub-api 容器；活动进度、券、奖品和投递记录保留。
如需卸下某服观察器，运行 `disable <服>`，同样等待无人，只从当前启动命令移除活动参数，保留同时期其他改动。所有数据和备份保留。

API 版本 1.2.1；最后一个升级前备份位于 `/vol1/mc-client-hub/backups/upgrades/api-1.2.1-20260906T155939Z`。
游戏端不需要客户端专用活动 Mod；老统一端仍能正常进服，但活动操作入口需要 1.0.3。

1.0.4 使用 API 1.2.3，升级前备份 `/vol1/mc-client-hub/backups/upgrades/api-1.2.3-20260907T001355Z`；1.2.1 为历史记录。

## 首月运营

上线日起第 1 周展示一服冒险手册，第 2 周二服生存据点，第 3 周三服产线说明，第 4 周四服空岛工厂。展示均自愿，不按装备强度、规模或无限产量排名。月底从投稿中组织一次自愿主题参观，不要求跨服，不启用 QQ 自动刷屏。

查看待审核：`docker exec mc-client-hub-hub-api-1 dotnet Hub.Api.dll admin activities-review`。
审核：在上述命令后加 `<投稿 ID> approve` 或 `<投稿 ID> reject`。未批准的内容不出现在公开展示。

首周根据每日完成／领取次数、奖品投递数量、待投递数量及玩家实际耗时反馈调后续配置，保留已得奖励和保底。`activity-report.py` 只读输出汇总，不输出账号名、凭据或令牌。
