# 下载与账号服务 FRP 配置

beta.8 使用单一入口 `https://launcher-direct.boshan.uk:21708`。现有 TCP 转发仍指向 124 的 `127.0.0.1:18080`，该端口由带有效证书的网关处理 TLS，`/v1/` 转发内部账号 API，文件从公开目录读取。配置见 `deploy/direct-tls.nginx.conf`。新版客户端下载的对象统一为 `/objects/sha256/{sha}`，原始来源只用于维护端提前准备内容。

旧版已经发布的 HTTP 文件地址保留 GET/HEAD 与 Range 兼容；明文 `/v1/` 请求拒绝接受。HTTPS 入口已接通，三服对象导入和从该入口安装的最终状态见 `packs/beta8-acceptance.json`。

2026-09-05 13:17 核实：下载服务同时监听 `127.0.0.1:18080` 与 `192.168.5.124:18080`。运行在 124 宿主网络中的 FRP 客户端使用 `127.0.0.1`；其他局域网机器或独立容器网络使用 `192.168.5.124`。

已接通入口：`http://103.40.14.100:21708` → `127.0.0.1:18080`。公网健康检查返回 200，实际 64 KiB 文件下载与 SHA256 校验通过，Range 请求返回 206 且内容正确。临时测试文件已删除。此变更只重建 downloads，其他容器启动时间保持不变。该入口尚未确认对应的线路名称。

河北阿里云、宿迁三网是两条平级的游戏连接线路；本版下载使用上述统一入口，选服页面切换游戏线路不切换下载源。

| 面板字段 | 值 |
| --- | --- |
| 隧道名称 | `mojin-downloads` |
| 隧道类型 | `TCP` |
| 本地地址 | `127.0.0.1`（frpc 运行在 124 宿主网络） |
| 本地端口 | `18080` |
| 远程端口 | 对应节点实际分配的空闲端口 |

如果 frpc 使用独立容器网络，`127.0.0.1` 指向 frpc 容器自身，此时填写 `192.168.5.124` 并确认容器可访问该地址。用户当前运行的 frpc 与 124 宿主处于同一网络命名空间，使用回环地址已实测可用。

使用 TOML 时，在对应节点已有的 frpc 配置中追加代理块，保留原有 `serverAddr`、`serverPort` 和认证配置：

```toml
[[proxies]]
name = "mojin-downloads"
type = "tcp"
localIP = "127.0.0.1"
localPort = 18080
remotePort = 21708 # 已配置入口；其他节点替换为实际分配的端口
```

此配置使用已有下载 TCP 隧道，不替换已有游戏代理。保持穿透面板分配的节点、远程端口和认证配置，不需要为本版另建第二条下载线路。

检查：

1. 在 124 访问 `http://127.0.0.1:18080/health`，应返回 `ok`；其他局域网机器使用 `192.168.5.124`。
2. 从外网访问 `https://launcher-direct.boshan.uk:21708/health`，确认 TLS 校验正常并返回 200；兼容 HTTP `/health` 返回 `ok` 不足以证明 HTTPS 配置正确。
3. 根路径 `/` 没有索引页，返回 404 不代表故障。
4. 完成统一入口的实际文件下载、SHA256 和断点续传检查，并确认全部必需对象已预存。健康检查不代表三服内容已经发布。

下载服务仅公开 `/vol1/mc-client-hub/public`，不需要账号密码或访问令牌。文件清单通过 HTTPS 获取并验证 ECDSA 签名，下载文件按清单验证 SHA256。

账号 API 的 `127.0.0.1:18081` 是内部 HTTP 接口，不直接向公网映射。新版通过已配置 TLS 的统一网关访问；旧 `launcher.boshan.uk` Tunnel 入口保留兼容，不作为新版玩家侧的自动后备。FRP 传输加密不能替代玩家到公网入口之间的 HTTPS。

参考：[FRP TCP 配置](https://gofrp.org/en/docs/examples/ssh/)、[FRP HTTP 与 HTTPS](https://gofrp.org/en/docs/examples/vhost-http/)。
