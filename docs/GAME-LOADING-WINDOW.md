# 四服启动加载窗

2026-09-06：本地实现，未推送、未打包发布、未改生产服务。和入服认证的上线时机一样，等待用户通知。

## 展示

四服共用无标题栏的 960 × 540 加载窗，分别使用大厅现有的魔法森林、废土、工业、空岛主题图。名称及关闭按钮直接叠在图片上；底部只有面向玩家的加载提示、总进度百分比和进度条。不显示模组、阶段计数、采样、窗口句柄等内部文案。窗口按显示器可用范围缩小，内容等比适配，不增加滚动。

启动 Java 后暂时隐藏本次进程的 Minecraft / GLFW / LWJGL 窗口。检测到实际开始连接服务器的输出时还原游戏窗口，确认窗口已可见且未最小化才关闭加载窗：一、三、四服使用现有 `MojinAutoConnect` 发出的连接信号，二服使用 Minecraft 的 `Connecting to …` 日志。兼容普通文本和 CmlLib 配置的 Log4j XML 消息。

“显示游戏”、右上角关闭及 Esc 都可以提前显示原游戏窗口，不结束游戏进程。游戏退出时关闭加载窗；遇到需要操作的原生对话框或超过 15 秒收不到组件心跳时也还原游戏，避免窗口永久隐藏。只操作本次启动 JVM 的窗口，使用异步 Win32 显隐，避免加载中的游戏线程阻塞统一端界面。

## 百分比来源

使用约 5.6 KiB 的 Java 8 兼容只读 javaagent，随统一端附带，不要求四个整合包各自增加一个模组，也不修改游戏类、替换加载监听器或调用游戏初始化函数。

| 加载器 | 读取接口 |
| --- | --- |
| Forge 1.7.10，一服/四服 | `cpw.mods.fml.common.ProgressManager.barIterator()` 中 Loader 持有的总 `Loading` 条 |
| Cleanroom 1.12.2，三服 | `net.minecraftforge.fml.common.ProgressManager.barIterator()` 中总 `Loading` 条 |
| Forge 1.20.1，二服 | 当前加载画面中 `ReloadInstance.m_7750_()` 的真实任务汇总；标准画面的 `Minecraft Progress` 作为同类备用读取入口 |

只读取加载器自身的总加载条，忽略子模组或单项材质条，避免反复从 0% 到 100%。未上报总计数时保留 0%，之后只随真实总计数推进；临时没有总条、加载器移除条、等待窗口时均保留已经达到的数值。加载器的总条到达终点后先保持 99%，收到真实连接信号后到 100%，并一直保留到窗口显示成功。

该百分比表示加载器的工作进度，**不等于耗时比例或剩余时间预测**。旧版原生总条只有七步，因此进度会分段跳动；新版 Minecraft 汇总条在资源加载建立后才出现，此前保持 0%。不把早期子任务的百分比冒充全程进度，也不根据历史耗时或定时器填充数字。

组件在后台每 350 ms 写一个不足 4 KiB 的本地状态快照；UI 异步读取。每次启动独立随机文件名，避免上次残留或同时启动其他服串状态。进入连接阶段后通知采样线程停止；游戏进程结束清理本次状态文件，保留可复用的按哈希命名的小组件。

Java 9+ 模块环境只向该组件开放实际需要的进度包和加载画面字段所在包。不读取账号、网络令牌、聊天或游戏存档。二服在已经观察到模组初始化事件后才查询 Minecraft 现有实例，避免提前触发游戏初始化。标准输出持续排空以免管道堵塞，原始输出不在此组件中缓存或写入额外日志。

## 本地副本实测记录

独立副本位于 `.local/loading-live-20260906`，使用固定内容清单和只读共享 Java，不修改用户正式实例。测试账号 `LoadingAudit` 只连接本机 TCP 测试端口，用于验证进入连接阶段及游戏窗口交接，不代表生产服务器入服验收。

四服首次实测发现并修复：Log4j XML 未识别；按一次异步显隐调用就结束交接；旧测试程序在交接后 1.5 秒关闭游戏，造成短暂出现后消失和进程残留。测试程序现保留窗口等待手动正常退出，保留原失败记录。

窗口控制不再将 `SW_HIDE` 放入 JVM 的 STARTUPINFO；只隐藏实际观察到可见的渲染窗口。恢复时只处理本次实际隐藏过的窗口或已经可见的新游戏窗口，不恢复原本就隐藏的后台窗口。显式排除 `GLFW message window`、`GLFW3 Helper`、`MC - Shared Drawable` 等消息及共享绘图窗口，避免多余窗口和任务栏图标。异步还原后确认可见才交接，进度条不受恢复耗时影响。

四服修正版已完成真实总计数、隐藏、实际本机连接、窗口交接和正常退出；用户确认总进度、末尾保持及窗口显示正常。该轮反馈的图标问题随后修复：加载窗显式使用品牌 PNG 图标，恢复渲染窗口时清除 TOOLWINDOW、设置 APPWINDOW，并异步刷新窗口样式，确保任务栏能列出游戏，保留游戏原有图标。

一服已完成加载、窗口交接、正常退出，用户确认游戏和加载窗图标均已正常。按追加反馈，加载窗不再单独占任务栏入口；主窗口设置为启动后隐藏时，在加载期间先最小化保留一个启动器入口，交接后再隐藏。

二服首轮及首次兼容修正均未通过总进度项：DrippyLoadingScreen 替换原生加载画面的绘制，保留但不更新 `Minecraft Progress`，使其一直为 0。改为优先读取实际 `ReloadInstance` 后已读到真实总进度。随后按用户反馈修正辅助窗口误显示；最后一次实测约 57 秒进入连接阶段，窗口清单确认仅 `DeceasedCraft` 可见，`GLFW message window` 保持隐藏，已正常退出。
