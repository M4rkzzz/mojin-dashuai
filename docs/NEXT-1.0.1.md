## #2 入服认证提示与历史角色自动关联

- 状态：客户端修改及管道回归已完成，已随 1.0.1 发布；服务端自动关联已随 API 1.1.1 热修复上线，统一端 1.0.0 已可使用。
- 问题：启动器返回角色关联或账号验证失败时，游戏端未读取返回的 `error`，而是因缺少 `ticket` 统一显示 `Join IPC unavailable`，导致玩家误以为本机通信故障。
- 已实现：正确接收并分类认证失败原因，区分角色归属或名称冲突、登录失效、认证服务网络错误，以及真正的本机通信失败；向玩家显示准确的中文提示和对应处理办法，不显示凭据、内部地址或原始技术异常。
- 历史角色处理：通过真实正版凭据和 Java 版所有权验证后，无其他账号归属冲突的同名旧角色自动关联，保留原大小写和离线 UUID。已有账号绑定不覆盖，官方改名不自动迁移存档。
- 已完成：四服 60 份玩家存档、50 组角色全部核对，补齐 21 条遗漏的历史名字记录；10 组已有绑定保留，其余 40 组在正版验证成功后自动关联。全部角色的隔离数据库验证已通过，不等同于全部玩家实际重登录验收。
- 遗留核实：`Alice/ALICE`、`Zongze/zongze` 存在历史大小写差异，保留当前 `Alice`、`zongze` 的群服账号绑定；归属核实前不合并不同 UUID 的存档。
- 验收：19 项实际 Windows 管道与 Java 8/17/25 客户端转换回归、3 项微软错误分类通过，覆盖角色冲突、登录失效、网络与超时、缺少启动器及正常票据。仅真实本机通信失败提示保持统一端运行；原始异常、地址、凭据不显示。此次客户端改动无需同步服务器组件或重启。

## #4 修复部分旧 Windows 上双击启动器无反应

- 状态：专项诊断包 `1.0.0-startup-debug.4` 已获故障玩家确认“正常”；兼容修复已随 1.0.1 安装包和自动更新包发布。
- 原因：该玩家使用 Windows 10 21H2 / 19044.2728，.NET 原生运行时因系统 CET 支持不完整，在进入主程序代码前退出。诊断报错为 `Your Windows doesn't fully support CET`，异常码 `0x80131506`；与网络或缺少 WebView2 无关。
- 已实现（后续构建指引）：在 `src/Launcher.Desktop/Launcher.Desktop.csproj` 为正式启动器设置 `<CETCompat>false</CETCompat>`，使安装包和自动更新包中的启动 exe 均采用已验证的兼容方式。只调整本应用的 CET 硬件栈保护标记，不修改 Windows 全局设置；无需默认开启诊断兼容模式、禁用 GPU 或跳过更新检查。
- 构建指引：参照 `tools/build-startup-diagnostics.ps1` 的处理，重新生成本项目 `obj` 下的原生 `apphost.exe`，避免 SDK 增量缓存复用仍启用 CET 的旧宿主；用 `python tools/check-apphost-cet.py <发布目录>/MojinDashuai.Launcher.exe --expected disabled` 校验实际 PE 标记，不能只检查构建参数。
- 验收：玩家已验证完整诊断包可以正常启动；正式 1.0.1 发布 exe 的实际 CET 标记为关闭，安装包与自动更新包检查均校验这一标记，正常启动及更新流程保留。此结果不代表所有旧 Windows 版本均已验收。
- 排查及诊断包说明见 [启动无反应诊断记录](STARTUP-DIAGNOSTICS.md)。
